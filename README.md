# タスク管理ボード（tool-task-board）

顧客ごとの作業タスクを「予定 / 作業中 / 完了」の3つの状態で管理する、小さな業務用Webアプリです。
FileMaker開発者（Web未経験）が、AI（Claude Code）に頼みながら設計から公開までを行いました。
その依頼の流れも [6. AIへの依頼の流れ](#6-aiへの依頼の流れ) にまとめています。

- 公開URL：https://tool-task-board.pages.dev/
- 入るときにユーザー名とパスワードが必要です（Basic認証 ※ブラウザ標準の入力窓で入れる人を制限する仕組み）。
  **ユーザー名・パスワードはこのファイルには書きません。** 管理者に確認してください。
- 入っているのはダミーデータだけです。**実在の顧客名・案件名・社内システムのID/パスワードは入力しないでください。**

```
task-dashboard/                ← GitHub の tool-task-board（公開リポジトリ）
├── README.md                  ← いまここ（サイトには載りません）
├── .gitignore                 GitHubに送らないファイルの一覧
├── functions/
│   └── _middleware.js         Basic認証の門番（サイトには載りません）
└── public/                    ← この中だけがサイトとして公開されます
    ├── index.html             アプリ本体（画面・動き・ダミーデータすべてこの1ファイル）
    └── robots.txt             検索エンジンに「巡回しないで」と伝えるファイル
```

## 1. できること

| 機能 | 内容 |
|---|---|
| かんばん画面 | 「予定｜作業中｜完了」の3列に、タスクがカードで並ぶ。PCでは横3列、スマホでは縦1列 |
| 顧客ごとの件数 | 画面上部のチップ（顧客名のボタン）に「予定◯ / 作業中◯ / 完了◯」を表示。押すとその顧客だけに絞り込み |
| タスクの登録・編集・削除 | 顧客・タスク名・状態・期限日・担当者・内容メモ |
| 状態の変更 | カードの「作業中へ ▶」「◀ 予定へ」ボタンで1つずつ移動 |
| 期限切れの表示 | 期限日を過ぎた未完了のタスクは赤字で「期限切れ」 |
| 顧客の登録・編集・削除 | 顧客名・表示順・備考。**顧客を削除すると、その顧客のタスクも一緒に削除** |
| ダミーデータに戻す | 画面下のボタンで、架空の3社・10件の初期状態に戻せる |

## 2. 使い方

### 開く
1. ブラウザで https://tool-task-board.pages.dev/ を開きます。
2. ユーザー名とパスワードの入力窓が出たら入力します。
   - 一度入ると、ブラウザを完全に閉じるまでは聞かれません。
3. スマホでよく使う場合は、ホーム画面に追加しておくと便利です。
   - **iPhone**：［共有］（□に↑）→［ホーム画面に追加］
   - **Android**：［︙］→［ホーム画面に追加］

### タスクを追加する
1. 右上の **［＋ タスク追加］** を押します。
   - 各列の見出しの横にある **［＋］** から追加すると、その列の状態（例：作業中）が最初から選ばれた状態になります。
   - 顧客で絞り込んでいるときに追加すると、その顧客が最初から選ばれた状態になります。
2. **顧客** と **タスク名** を入力します（この2つは必須です）。
3. 必要に応じて、状態・期限日・担当者・内容メモを入力します。
4. **［保存］** を押します。

### タスクを直す・消す
- 直す：カードの **［編集］** → 内容を直して **［保存］**
- 消す：カードの **［削除］** →「よろしいですか？」で **［OK］**
- 状態だけ変える：カードの **［作業中へ ▶］** などを押します

### 顧客を管理する
1. 右上の **［顧客管理］** を押します。
2. 一覧の **［編集］** で直す、**［削除］** で消す。下の入力欄に入力して **［追加］** で新規登録です。
   - 表示順は、チップの並び順になります（小さい数字ほど左）。
   - ⚠️ 顧客を削除すると、**その顧客のタスクもすべて消えます**（元に戻せません）。

### 絞り込む
- 上部のチップで顧客名を押すと、その顧客のタスクだけが表示されます。
- もう一度押すか、**［全顧客］** を押すと絞り込みが解除されます。

## 3. データの保存場所（大事）

データは、**使っているブラウザの中**（localStorage ※ブラウザ内の小さな保存領域）にだけ保存されます。サーバー（※ネット上のコンピュータ）には送られません。

| こうなります | 理由 |
|---|---|
| Aさんが登録したタスクは、Bさんには見えない | 人ごとにブラウザが別だから |
| 同じ人でも、PCとスマホでは中身が別 | 端末ごとにブラウザが別だから |
| ブラウザの履歴・データを消すと、タスクも消える | 保存領域ごと消えるから |
| アプリを更新しても、登録したタスクは残る | 保存領域はアプリのファイルとは別だから |

FileMakerで例えると、**ファイルを各自のPCにコピーして、それぞれで使っている状態**です。
チームで同じデータを共有したくなったら、データベース（※データを1か所にまとめて保管する仕組み）の追加が必要です。

## 4. 項目（FileMakerのフィールド定義の形式）

リレーションは **顧客 1 : 多 タスク**（顧客::顧客ID = タスク::顧客ID）です。

**顧客**

| フィールド名 | プログラム上の名前 | タイプ | オプション |
|---|---|---|---|
| 顧客ID | `id` | テキスト | 自動入力：UUID（`Get(UUID)` 相当） |
| 顧客名 | `name` | テキスト | 空欄不可 |
| 表示順 | `order` | 数字 | 自動入力：今の最大値＋1 |
| 備考 | `note` | テキスト | |
| 作成日時 / 修正日時 | `createdAt` / `updatedAt` | タイムスタンプ | 自動入力 |

**タスク**

| フィールド名 | プログラム上の名前 | タイプ | オプション |
|---|---|---|---|
| タスクID | `id` | テキスト | 自動入力：UUID |
| 顧客ID | `customerId` | テキスト | 空欄不可（照合フィールド） |
| タスク名 | `name` | テキスト | 空欄不可 |
| 状態 | `status` | テキスト | 値一覧「予定 / 作業中 / 完了」、初期値「予定」 |
| 期限日 | `due` | 日付 | |
| 担当者 | `assignee` | テキスト | |
| 内容メモ | `memo` | テキスト | |
| 作成日時 / 修正日時 | `createdAt` / `updatedAt` | タイムスタンプ | 自動入力 |

顧客ごとの件数は保存せず、画面を表示するたびに数えています（FileMakerの集計フィールドに相当）。

## 5. 公開のしくみと更新のしかた

### しくみ

```
手元の task-dashboard/
   │  git push（※手元の変更をGitHubへ送る）
   ▼
GitHub：sup-tsato/tool-task-board（公開）
   │  変更を検知して自動で取り込む
   ▼
Cloudflare Pages（※Webページを無料で公開できるサービス）
   │  functions/_middleware.js が門番としてユーザー名・パスワードを確認
   ▼
https://tool-task-board.pages.dev/
```

| 設定 | 値 |
|---|---|
| GitHubリポジトリ | `sup-tsato/tool-task-board`（**公開**：プログラムと履歴は誰でも見られる） |
| Cloudflare に読ませるリポジトリ | `tool-task-board` だけ（Only select repositories） |
| ビルドコマンド | `exit 0`（変換作業なし） |
| ビルド出力ディレクトリ | `public`（この中だけを公開） |
| 環境変数（本番・シークレット） | `BASIC_AUTH_USER`（ユーザー名）、`BASIC_AUTH_PASS`（パスワード） |

### 検索エンジン対策（noindex）
次の3か所で「検索結果に載せないで」と伝えています。
- `public/index.html` の `<meta name="robots" content="noindex, nofollow">`
- `public/robots.txt`（パスワードなしで読めるようにしてあります。ロボットはパスワードを入力できないためです）
- すべての応答に付けている `X-Robots-Tag: noindex, nofollow` ヘッダー（※ページ本体の外側に付ける付加情報）

### アプリを直したいとき
1. `public/index.html` を直します（AIに「〇〇を直して公開して」と頼めば、修正から公開後の確認まで行います）。
2. コミット（※変更の記録）して、GitHubへプッシュ（※送信）します。
3. 1〜2分で、公開ページに自動で反映されます。
4. 反映されないときは、Cloudflare の［Workers & Pages］→［tool-task-board］の公開履歴（デプロイ一覧）を確認します。前の版に戻したいときは、その画面の **ロールバック**（※以前の状態に戻す操作）を使います。

### 手元で動かしたいとき
`public/index.html` をダブルクリックすると、ブラウザで開けます（パスワードはかかりません）。
手元で開いたときのデータは、公開URLで開いたときのデータとは別に保存されます。

### パスワードを変えたいとき
1. 新しいパスワードを作ります（AIに「パスワードを変えて」と頼めば作ってくれます）。
2. Cloudflare の［Workers & Pages］→［tool-task-board］→［設定］→［変数とシークレット］で、`BASIC_AUTH_PASS` の値を新しいものに変えて保存します。
3. 変更を反映させるため、公開し直します。Cloudflare の公開履歴から「再デプロイ」を行うか、AIに「再デプロイして」と頼みます。

### 安全のための決まりごと
- このリポジトリは**公開**です。ファイルもコミット履歴も、誰でも見られる前提で扱います。一度送ったものは、あとで消しても履歴やコピーに残ることがあります。
- ユーザー名・パスワードは、**コード・README・コミットには絶対に書かない**（Cloudflareの環境変数にだけ置く）。
- 環境変数が未登録のときは、門番が**誰も入れない状態（503）にする**ので、設定漏れでサイトが開きっぱなしになることはありません。
- コミットの作者は GitHub の表示専用アドレス（noreply）にしてあり、会社のメールアドレスは履歴に残していません。
- 手元で試すときの秘密ファイル（`.dev.vars`、`.env`）は、`.gitignore` でGitHubに送らないようにしています。
- Basic認証は簡易的な鍵です。重要な情報を入れる用途には使わないでください。

## 6. AIへの依頼の流れ

Claude Code（VS Code の拡張機能）に、日本語で次の順番で頼みました。
各段階で「AIが案を出す → 人が選ぶ・確認する → 次へ」を繰り返しています。

### 全体の流れ

| # | 段階 | 人が頼んだこと | AIがやったこと | 人が決めたこと |
|---|---|---|---|---|
| 1 | 設計相談 | 作りたいものと条件を伝え、「**実装はまだしないで**」と前置きして、①項目定義（FileMakerのフィールド定義の形式）②画面構成 ③技術の選択肢2案と詰まりそうな箇所 ④質問リスト、を依頼 | 顧客・タスクの2テーブル案、画面3枚＋確認ダイアログ、「スプレッドシート＋GAS」と「Supabase＋Vercel」の比較、確認したいこと10項目を提示 | 技術は**HTML1枚・手元で動かす**、一覧は**かんばん型**、顧客の削除時は**タスクも削除** |
| 2 | 実装 | 選んだ内容で作成 | `index.html` を作成。登録・編集・削除などを自動テスト（16項目）し、PC幅とスマホ幅の画面写真で表示崩れも確認 | 手元で動作を確認 |
| 3 | 公開 | Cloudflare Pagesに、GitHub連携で公開したい。手作業は**番号付きで1ステップずつ**、待ちの箇所は「**ここで止まってください**」と明示、公開前に**鍵・個人情報の点検**、を依頼 | 全体の手順（8ステップ）を先に一覧で提示。点検 → git準備 → 非公開リポジトリの作成と送信までを自動で実行。Cloudflareの画面操作は日本語表示で案内 | リポジトリは**非公開**、名前は `tool-task-board` |
| 4 | 公開後の保護 | ①点検（ファイルとコミット履歴）②noindex（metaタグとrobots.txt）③Basic認証（Pages Functionsの`_middleware`で、認証情報は環境変数から読む）④パスワードの生成と登録、を依頼 | 履歴まで点検。noindex と門番プログラムを作成し、動作テスト（11項目）。パスワードを生成して一度だけ表示。登録後に、入れる・入れない・noindex・非公開ファイルを本番で確認 | Cloudflareの画面で環境変数とビルド設定を登録 |
| 5 | 資料化 | このREADMEの作成 | 使い方・しくみ・依頼の流れを整理 | — |
| 6 | リポジトリの公開 | 「リポジトリを公開するのを忘れていた」と相談 | 「サイトの公開」と「リポジトリの公開」の違いと、公開したときの影響を説明して目的を確認。READMEを送り、全履歴を再点検してから public に切り替え | 誰でも見られるように**公開** |

### 途中で詰まったところと、その解決

| 詰まったところ | どう頼んだか | 解決 |
|---|---|---|
| Cloudflareの画面が英語で分かりにくい | 「日本語版で説明して」 | 日本語表示の名前と英語の名前を並べた手順に作り直してもらった |
| GitHubのログインで2段階認証のコードを求められた | 「これはどうすれば取得できますか？」 | スマホの認証アプリの探し方と、パスキーやリカバリーコードなどの代わりの方法を案内してもらった |
| 「Only select repositories」の操作が分からない | 「画像を生成して教えて」 | 押す場所に番号を付けた説明用のイメージ図を作ってもらった |
| その画面への行き方が分からない | 「どの項目を選んだらこの画面になりますか？」 | 途中で出る確認画面の見分け方と、別の行き方（GitHubの設定画面から開く方法）を案内してもらった |
| 「Install & Authorize」ボタンが見つからない | 見えている緑のボタンの名前（「Add a README」「Code」）を伝えた | 別の画面（リポジトリのページ）にいたことが分かり、Cloudflareの画面に戻る道を案内してもらった |

### うまくいった頼み方
- **最初に「実装はまだしないで」と言い、設計案と質問リストを先に出してもらう**：作り始めてからの手戻りが減ります。
- **「専門用語には短い注釈を付けて」「FileMakerの形式で」と条件にする**：Webの知識がなくても判断できる説明になります。
- **手作業は「番号付きで1ステップずつ」、待ちは「ここで止まってください」と明示してもらう**：今どこで止まっているかが分かりやすくなります。
- **分からない画面は、見えている文字をそのまま伝える**：AIが今どの画面にいるかを推測できます。
- **「鍵や個人情報がないか点検して」と毎回はっきり頼む**：公開前の事故を防げます。
- **パスワードや認証コードはチャットに貼らない**：AIが一度だけ表示したパスワードも、すぐにパスワード管理アプリへ移します。

## 用語メモ

| 用語 | 意味 |
|---|---|
| リポジトリ | GitHub上のファイル置き場 |
| コミット / プッシュ | 変更を記録として保存すること / その記録をGitHubへ送ること |
| デプロイ | 作ったものを公開すること |
| Cloudflare Pages | Webページを無料で公開できるサービス。GitHubへの送信を検知して自動で公開する |
| Pages Functions / `_middleware` | ページを表示する前にCloudflare側で動く小さなプログラム / その中で、すべてのページの手前に立つ門番役 |
| 環境変数（シークレット） | コードとは別の場所に保管する設定値。パスワードなどを暗号化して置ける |
| Basic認証 | ブラウザ標準のユーザー名・パスワード入力窓で、入れる人を制限する仕組み |
| noindex | 検索エンジンに「このページを検索結果に載せないで」と伝える目印 |
| localStorage | ブラウザの中にある小さな保存領域。端末・ブラウザごとに別々 |
| UUID | 重複しない長いランダムなID（FileMakerの `Get(UUID)` と同じ） |
